# Мониторинг сетевого трафика «ТехноПрофи»

Домашнее задание к лекции от 17.11.2026 по обеспечению информационной безопасности бизнес-процессов.

## Запуск

Требуется Python 3.10 или новее. Команды выполняются из папки проекта.

```powershell
python monitor.py
python roi.py
```

Пример содержит 232 записи о пакетах. Программа читает одну строку CSV на пакет и группирует записи по секунде UTC и IP назначения. Подозрение на DDoS фиксируется, если достигнуты оба порога: 100 пакетов в секунду и 3 разных IP источника. Пороги меняются параметрами `--pps` и `--min-sources`.

| Интервал UTC | Пакетов/с | Источников | Результат |
|---|---:|---:|---|
| 08:00:00 | 12 | 4 | Ниже порога |
| 08:00:01 | 120 | 4 | Подозрение на DDoS |
| 08:00:02 | 100 | 1 | Меньше трёх источников |

`report.json` содержит число пакетов по протоколам, подозрительные интервалы и совпадения с индикаторами угроз. Алгоритм использует фиксированные секундные окна и предназначен для разбора выгрузок. Пороговое совпадение требует проверки оператором.

## Аудит и оповещения

В `audit.jsonl` добавляются начало и результат обработки, импортированные события, срабатывания детектора, совпадения с индикаторами и результат доставки по каждому каналу. Запись содержит время в UTC, действие, статус и детали. Это поддерживает журналирование и мониторинг по ISO/IEC 27001:2022, приложение A, меры 8.15 и 8.16. Для эксплуатации организация задаёт права доступа, сроки хранения, защиту записей от подмены и централизованный сбор.

Обычный запуск показывает режим `preview`. Для реальной отправки укажите переменные окружения `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и/или `SLACK_WEBHOOK_URL`, затем выполните `python monitor.py --send`. В сообщении передаётся число срабатываний. Ключи и адрес вебхука хранятся вне Git. При отправке возможны статусы `sent`, `failed` и `unconfigured`.

## Интеграции

| Модуль | Вход | Результат |
|---|---|---|
| Биометрическая аутентификация | `--biometric`, JSON с событиями `timestamp`, `source_ip`, `outcome` | Импорт результатов проверки доверенного поставщика в аудит. Биометрические образцы остаются у поставщика |
| AWS | `--aws`, выгрузка CloudTrail в JSON | Импорт действий, времени, IP и результата |
| Azure | `--azure`, ответ Activity Log API в JSON с массивом `value` | Импорт операций, времени, IP и результата |
| MISP | `--misp`, JSON выгрузки Attribute Search с массивом `response.Attribute` | Сопоставление IP-атрибутов с флагом `to_ids` с IP пакетов |
| OTX | `--otx`, JSON выгрузки pulses с массивом `results` | Сопоставление IPv4/IPv6 из индикаторов с IP пакетов |

По умолчанию используются локальные учебные выгрузки. Адаптеры работают через импорт файлов. Используйте `python monitor.py --help`, чтобы посмотреть параметры.

Форматы событий описаны в документации [AWS CloudTrail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-record-contents.html) и [Azure Activity Log](https://learn.microsoft.com/en-us/azure/azure-monitor/platform/activity-log-schema).

| Показатель | Расчёт | Сумма, руб. |
|---|---|---:|
| Сокращение расходов на расследование и реагирование | С 4 до 2 инцидентов в год × 1 000 000 руб. | 2 000 000 |
| Экономия от сокращения простоя | С 20 до 10 ч × 50 000 руб./ч | 500 000 |
| Сокращение прямых потерь от утечек | С 1 000 000 до 500 000 руб. в год | 500 000 |
| Общая годовая экономия | Сумма трёх статей | 3 000 000 |
| Затраты первого года | Внедрение 450 000 + эксплуатация 200 000 | 650 000 |
| Чистый экономический эффект | 3 000 000 − 650 000 | 2 350 000 |

Простой сокращается на 50%. При круглосуточной работе (8 760 ч/год) доступность растёт с **99,7717%** до **99,8858%**. В расходы на расследование входят работы по реагированию. Простой и прямые потери от утечек учтены в отдельных строках.

**ROI первого года = (3 000 000 − 650 000) / 650 000 × 100% = 361,54%.**
